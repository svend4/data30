# Разрешение конфликтов в планах

Этот документ описывает, как переносить изменения из конфликтных планов
в единую структуру `plans/`.

## 1) Базовое правило

Все актуальные планы находятся в каталоге `plans/`. Старые файлы вроде
`project_plan.md`, `PLAN.md`, `plan.md` считаются устаревшими источниками.

## 2) Как переносить изменения

1. Откройте конфликтный файл (например, `project_plan.md`).
2. Найдите соответствующий целевой файл в `plans/`:
   - `project_plan.md` → `plans/plan-roadmap.md`
   - `PLAN.md` → `plans/plan-raci.md`
   - `plan.md` → `plans/plan-prototype.md`
3. Перенесите смысловые изменения в целевой файл.
4. Удалите/игнорируйте устаревший файл, чтобы не вернуть его обратно.

## 3) Минимальный чеклист

- [ ] Изменения перенесены в корректный файл внутри `plans/`.
- [ ] Дубли не добавлены (проверьте заголовки и разделы).
- [ ] Устаревшие имена планов не восстановлены в корне репозитория.
